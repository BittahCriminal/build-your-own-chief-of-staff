# Six things before a workflow changes

Original: [enterprise-ai-deployment-layer](https://natesnewsletter.substack.com/p/enterprise-ai-deployment-layer).

## What we took

Workflow design, data access, authority, evaluation, audit trails, recovery/ownership. Buying a model is not changing a process. Some workflows should not be automated at all.

## How this kit applies it

The six requirements translate into this kit as follows: the [SOP](../../prompts/process/write-the-sop.md) describes the work; the private [sources file](../../context-templates/sources.md) names the evidence and access; draft-only rules limit authority; [Verify](../../prompts/process/verify.md) defines evaluation; retained sources and reviewed outputs provide a trail; and [Correct the file](../../prompts/process/correct-the-file.md) supports an owner's repair loop.

**Check in practice:** Identify the steps, accessible inputs, allowed actions, acceptance criteria, evidence of the run, and person responsible for recovery. A model subscription alone supplies none of these decisions.
