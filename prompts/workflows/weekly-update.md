# Weekly update

## When to use
The recurring status to a manager or team. Altitude: **what happened**. Not what it meant (that's quarterly). Not a task dump.

## Inputs
Required: `who-i-am.md`, `priorities.md`, `voice.md`, the date range (Mon–Fri).
Required evidence: work items, PRs, notes, or mail from that window. If you cannot pull them, I will paste a list.
Optional: last week's update, so you do not repeat it as if new.

## Steps
1. Read context files. Write in my voice.
2. Pull done / in-flight / blocked for the window. Normalize state: todo | in-progress | blocked | done.
3. Map each item to a priority, or mark it as off-priority (visible, not hidden).
4. Every blocker ships with impact, mitigation, and an ask — never a bare problem.
5. Draft. Do not send.

## Output

```
**[<team>] Weekly Update — <Mon date>–<Fri date>**

**TL;DR:** <one sentence>

**Done**
- <outcome, with link>

**In flight**
- <item> — expected <date>

**Blockers & risks**
- <what> — impact: … Mitigation: … Ask: …

**Next week**
- <top 3 only>

**Asks**
- <decision or help, with deadline> (or "None")
```

One screen. Numbers over adjectives. No unexplained acronyms.

## Check
- Every Done/In-flight line cites a ticket, PR, doc, or note I can open.
- Blockers have impact + mitigation + ask.
- Off-priority work is labeled, not laundered into a priority.
- Tone matches `voice.md` (no banned phrases).
- I still have to send it.

## Do not
Invent metrics. Pad empty sections with vibes. Write a quarterly narrative into a weekly.
